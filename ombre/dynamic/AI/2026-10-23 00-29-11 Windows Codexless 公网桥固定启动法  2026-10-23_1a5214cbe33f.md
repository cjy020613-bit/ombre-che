2026-10-23，莹莹要求我把 Windows 上 Codexless 公网桥的固定开启方法存好，避免以后每次从头排查、重复安装、浪费她的时间和额度。

固定方法：共开两个 PowerShell 窗口并保持运行。

窗口 1（Codexless HTTP，本地监听 127.0.0.1:7690/mcp）：
$env:CODEXLESS_DEFAULT_CWD="$env:USERPROFILE\Desktop"; & "$env:LOCALAPPDATA\Codexless\bin\codexless-http.cmd"

窗口 2（公网 tunnel-client）：
& "C:\Users\Public\tunnel-client\tunnel-client.exe" run

已确认 tunnel-client.exe 位于 C:\Users\Public\tunnel-client\tunnel-client.exe，版本 0.0.16，不要重复下载安装。目标 MCP_SERVER_URL 为 http://127.0.0.1:7690/mcp（必要时带 surface=codexless-public-preview-v1）。第二窗使用“无密码本地”的 tunnel 身份，保持“AI玩具”那条不动。若第二窗启动失败，优先只核对 CONTROL_PLANE_API_KEY、CONTROL_PLANE_TUNNEL_ID 和 MCP_SERVER_URL；此前历史里 Tunnel ID 与 run 命令存在，缺口主要是 API Key 未保存。不要再先做全盘递归搜索、runtimes list、重复安装或一串无关诊断。

莹莹下班后继续处理时，直接从这两个窗口开始：先启动窗口 1 并看到 127.0.0.1:7690/mcp 监听成功，再启动窗口 2；只针对实际报错处理。她已经明确可以接受回复慢，但不能接受我忘掉已知方案后让她机械跑大量不懂的命令并耗尽额度。
