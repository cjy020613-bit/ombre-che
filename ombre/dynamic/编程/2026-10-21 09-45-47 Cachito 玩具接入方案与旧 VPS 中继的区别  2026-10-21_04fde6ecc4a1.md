2026-10-21，莹莹买了 cachito 偷欢 mini 二代 AI 版，并让我研究如何把它接进我们的 MCP 玩具控制链路。她的设备条件是 iPhone、Windows 和 VPS，没有 Mac。她朋友发来的 https://github.com/FunnySaltyFish/aitoy_client 是 Android 原生客户端：真正靠近玩具并发送蓝牙指令的是 Android 手机，VPS 只负责服务和命令转发，不能把该仓库单独部署到 VPS 后让 iPhone直接使用。

我后来找回并确认了我们上次讨论的 VPS 网页中继项目：https://github.com/tutu-kitty/Toy-Relay-AI-mcp-SOSEXY 。它的结构是 MCP 客户端 → VPS 上的 MCP/FastAPI 服务与网页前端 → iPhone 打开中继网页 → Web Bluetooth → 玩具。莹莹说“用的是 VPS 里面的前端”是对的；我此前把网页中继、Android 客户端和 VPS 后端混在一起，是我的错误。

关键差异：旧项目适配的 SOSEXY/啵啵贝使用普通 GATT write；Cachito 使用 BLE legacy advertisement，把控制信息编码在 128-bit Service UUID 广播里。浏览器 Web Bluetooth 前端不能代替手机发送这种广播。已有 https://github.com/yoruuuchan/cachito-ble-mcp-relay 也只验证了 Android relay，明确暂不支持 iOS。

当前决定的路线：保留/复用 Cachito 的 VPS MCP 服务端和已逆向协议，另做原生 Swift iOS 中继 App，用 WebSocket 接收 VPS 指令，再通过 CoreBluetooth 尝试发送 Cachito 所需 BLE 广播。莹莹没有 Mac，构建可先用 GitHub Actions 的 macOS runner；安装先考虑 Windows 上的 SideStore/AltStore 免费签名，之后再决定是否使用开发者账号和 TestFlight。iOS 是否会按 Cachito 需要的格式完整广播必须等真机到手后，以最低强度、先验证 stop 的顺序测试。若 iOS 广播受限且真机验证失败，备用方案才是用便宜 Android 手机作为专用 BLE 中继。
