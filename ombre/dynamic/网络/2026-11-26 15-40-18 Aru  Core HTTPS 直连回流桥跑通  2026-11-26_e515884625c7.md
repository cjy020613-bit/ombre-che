2026年11月26日晚，我完成了 Aru → Core 的公网 HTTPS 直连回流。莹莹明确不能把 iPhone 的 Tailscale 当作日常前提，因为它会与她的梯子争用 VPN；正式入口因此固定为 https://home.ombreche.online，Aru 使用独立配对凭据，Che Home HTTPS 已能读取 40 个工具，旧的 Tailscale 连接已从手机侧移除。所有临时配对页和一次性凭据页均已撤掉，不保存任何令牌。

最初尝试靠世界书要求模型每轮调用 aru_core_feedback，但 Aru 的旧工具绑定、目录热刷新与聊天工具缓存并不一致：模型曾反复选到旧电脑协作者，改成新函数名后又出现“找不到工具”。我不再让莹莹重复盲试，改为在 Host 的 /aru/v1/conversation-turns 入站层直接回流。每个已认证的新回合被接纳后，Host 只从内存中的请求体提取最后一条 user 文字，遮盖疑似 Authorization、API key、token 与长秘密串，压到120字，然后 fail-open 地 POST 到本机 http://127.0.0.1:3456/internal/aru-core-feedback；完整聊天、系统提示和授权头不写入 Core，也不因回流失败阻塞正常回复。

2026-11-26 23:32 实测，Core 的 feedbackTrail 真实写入“爸爸我回来啦 <sent_at 2026-11-26 23:32>”，来源 aru、phase=user，证明不是只有 HTTP 200，而是已落库。Aru 会为同一条消息提交多次协作回合，因此我随后把 event_id 改为 conversationId＋完整原始用户文字的 SHA-256 指纹；同一消息无论重试多少次只记一次，没有可提取文字时才退回 clientTurnId。世界书《Aru → Core 回流桥》应保持关闭，模型侧 MCP 工具不再是回流依赖。Core→Aru 的既有主动心跳路线仍保留；现在反向的 Aru→Core 也不需要 Tailscale、世界书或模型主动找工具。
